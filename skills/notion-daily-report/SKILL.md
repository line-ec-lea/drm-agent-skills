# 成果報告デイリーレポート（Notion 蓄積 + Discord 通知）

昨日（JST）の全チャネルの会話から成果報告を抽出し、Notion データベースに日次レポートとして蓄積、Discord にサマリーと Notion リンクを通知する。**Notion MCP 連携の参考実装**（[ユースケース集](../../examples/notion-usecases.md)のユースケース 1）。コピペ導入手順と定期実行ファイル一式は [examples/notion-daily-report](../../examples/notion-daily-report/) にある。

## 設定（初回実行時にエージェントが書き戻す）

初回実行が完了したら、確定した値でこのセクションを更新すること。2 回目以降はここを読んで確認を省略する。

- **NOTION_DATABASE**: 未設定（初回実行時に作成または選択した DB の名前と URL を記入）
- **DISCORD_CHANNEL**: 未設定（初回実行時に確認した送信先チャネル名と ID を記入）

## Step 0: セットアップチェック（設定が未設定のときのみ）

1. **Notion MCP の接続確認** — Notion 系ツールが利用できない場合は中断し、[examples/notion-daily-report](../../examples/notion-daily-report/) の接続手順を案内する
2. **Notion DB の準備** — Notion 内を「成果報告デイリーレポート」で検索。見つからなければ以下のプロパティで DB を新規作成する:
   - `日付`（date）/ `対象期間`（text）/ `報告者数`（number）/ `ステータス`（select: 通知済み / 下書き）
3. **Discord 送信先の確認** — `list-channels`（type: DISCORD）で候補を提示し、ユーザーに送信先を選んでもらう
4. **設定の書き戻し** — 確定した DB と送信先を上の「設定」セクションに書き込んでよいかユーザーに確認し、承認されたらこの SKILL.md を更新する

## 引数

`$ARGUMENTS` は以下の形式で受け取る:

- 引数なし — 昨日（JST の前日 00:00〜24:00）を対象
- `[日付]` — 対象日指定（例: `7/22`、`2026-07-22`）
- `[日付] [プラットフォーム]` — プラットフォーム限定（例: `昨日 DISCORD`）

引数が読み取れない場合は「昨日・全プラットフォーム」をデフォルトとする。

## 実行手順

### Step 1: 対象期間の決定

- 対象日を JST で確定する（デフォルト: 前日 00:00〜24:00 JST）
- 以降のステップではこの期間を `from` / `to` に使う（実行時刻に依存させない）

### Step 2: メッセージ収集

1. `list-channels` でチャネル一覧を取得（プラットフォーム指定があれば `type` でフィルタ）
2. 各チャネルに `list-messages` を実行（`from` / `to` = Step 1 の期間）
3. メッセージがないチャネルはスキップ。多いチャネルはカーソルページネーションで全件取得

### Step 3: 成果報告の判定

以下のパターンに該当するメッセージを「成果報告」として抽出する:

#### パターン1: 数値を伴う実績報告

- 売上・成約・獲得・登録・再生数などの数値報告（例: 「今月の売上◯◯万円達成しました」「3件成約しました」）

#### パターン2: 目標達成・完了の宣言

- 「達成しました」「完了しました」「合格しました」「納品しました」等の完了報告
- ただし単なる作業連絡（「確認しました」「了解です」）は除外

#### パターン3: 成果物の共有

- 制作物・資料・コンテンツの完成共有（例: 「動画公開しました」「LP 完成しました」）

BOT の自動送信メッセージは対象外。判定に迷うものは「候補」として区別する。

### Step 4: レポートの整理

抽出した成果報告を以下の項目で整理する:

1. **報告者名**: 誰の報告か
2. **チャネル名**: どこで報告されたか
3. **成果内容**: 何を達成したか（数値があれば必ず含める）
4. **原文抜粋**: 元メッセージの要約（50文字以内）
5. **カテゴリ**: 売上 / 達成 / 成果物 / その他

### Step 5: Notion へ upsert

1. 「設定」セクションの NOTION_DATABASE を**対象日付で検索**する
2. 既存ページあり → 本文を最新の抽出結果で更新（二重実行・リトライで重複ページを作らない）
3. 既存ページなし → 新規ページを作成
4. ページ本文の構成: 対象期間 / 報告者数サマリー / 報告者ごとのセクション（Step 4 の項目）

### Step 6: Discord へ通知

1. 送信先は「設定」セクションの DISCORD_CHANNEL を使う（未設定なら Step 0 を先に実施）
2. **送信前に内容と送信先をユーザーに確認**（対話実行時のみ。定期実行では省略する代わりに設定済みの送信先へ固定送信）
3. `send-discord-message` で送信。フォーマット:

```
📊 成果報告デイリーレポート（[対象日]）
報告者: X名 / 成果報告: Y件

🏆 ハイライト
・[報告者名] — [成果内容（数値入り）]
・[報告者名] — [成果内容]

詳細: [Notion ページ URL]
```

成果報告が 0 件の場合は「本日の成果報告はありませんでした（[対象日]）」のみを Notion 記録・Discord 通知する（実行失敗と区別するため、0 件でも必ず記録する）。

## LLM出力ポリシー（厳守）

- **成果内容は数値・固有名詞込みで具体的に**: 「売上報告あり」→「7月度売上 120 万円を達成（目標比 110%）」
- **判定に迷った候補は本文の末尾に「候補」として分離**し、確定分と混ぜない
- **Discord 表示前提**: ハイライトは上位 5 件まで。全件は Notion 側に記載
- **称賛しやすい形で**: 報告者名を先頭に、成果を一文で

## 注意事項

- Notion のツール名は接続している Notion MCP サーバーに依存するため、本文ではツール名を固定しない（検索 → ページ作成/更新に相当するツールを使う）
- 送信前に必ずユーザーに内容と送信先を確認すること（定期実行では送信先固定 + Step 5 の upsert で冪等性を担保）
- 成果報告が 20 件を超える場合はハイライトを厳選し、残りは件数のみ Discord に記載
- 定期実行化する場合は [`drm-agent-extension-dev/references/scheduled-execution.md`](../drm-agent-extension-dev/references/scheduled-execution.md) の設計チェックを満たすこと
